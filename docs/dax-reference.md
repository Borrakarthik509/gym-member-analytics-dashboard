## Active Measures

All explicit measures are stored in the `Measure_table` — a disconnected measure island that separates business logic from raw data columns and keeps the field list clean in Report view.

---

### `avg_visit`

| Property | Value |
|----------|-------|
| **Table** | `Measure_table` |
| **Return Type** | Decimal |
| **Used In** | Visits card (KPI strip) |

```dax
avg_visit = AVERAGE('Gym Dataset'[visits])
```

**Business purpose:** Returns the mean number of gym visits per member within the current filter context. Responds to all three slicers (Gender, Group lesson, Steps category). A sudden drop after applying a trainer filter may indicate scheduling issues.

---

### `avg_age`

| Property | Value |
|----------|-------|
| **Table** | `Measure_table` |
| **Return Type** | Decimal |
| **Used In** | Age card (KPI strip) |

```dax
avg_age = AVERAGE('Gym Dataset'[age])
```

**Business purpose:** Returns the mean age of the filtered member population. A shift after applying a trainer or lesson filter reveals age skew in trainer assignments or class preferences — useful for targeted marketing.

---

### `avg_time`

| Property | Value |
|----------|-------|
| **Table** | `Measure_table` |
| **Return Type** | Decimal |
| **Used In** | Avg Time card (KPI strip) |

```dax
avg_time = AVERAGE('Gym Dataset'[session_time])
```

**Business purpose:** Returns the mean session duration in minutes. Members with a high visit count but low `avg_time` may be attending briefly without completing full sessions — a retention risk indicator.

## Implicit Measures Used in Visuals

These are not stored as named measures but are generated by Power BI's query engine at render time:

| Visual | Expression | Context |
|--------|------------|---------|
| Members card | `COUNTROWS('Gym Dataset')` | Total member count |
| Premium card | `MIN('Gym Dataset'[abonoment_type])` filtered to `"Premium"` | Premium member count |
| Standard card | `MIN('Gym Dataset'[abonoment_type])` filtered to `"Standard"` | Standard member count |
| Trainer donut | `COUNTNONBLANK('Gym Dataset'[id])` grouped by trainer | Members per trainer |
| Mood bar | `COUNTNONBLANK('Gym Dataset'[id])` grouped by Mood | Members per mood category |
| Combo chart | `AVERAGE('Gym Dataset'[active_minutes])` grouped by birth month | Avg activity by age group |
| Line chart | `SUM('Gym Dataset'[calories_burned])` by steps bucket | Calorie output by step tier |

> **Best practice note:** Converting these implicit measures to explicit DAX measures would improve model transparency and make the report easier to maintain. See the [Roadmap](../README.md#-future-improvements) for this planned enhancement.

## Recommended Next Measures

These measures would strengthen the dashboard's analytical value and are straightforward to implement:

### Premium Percentage

```dax
Premium % =
DIVIDE(
    CALCULATE(
        COUNTROWS('Gym Dataset'),
        'Gym Dataset'[abonoment_type] = "Premium"
    ),
    COUNTROWS('Gym Dataset'),
    0
)
```

**Use case:** KPI card or conditional formatting — shows what proportion of the membership base is on the higher-revenue tier.

---

### High Engagement Members

```dax
High Engagement Members =
CALCULATE(
    COUNTROWS('Gym Dataset'),
    'Gym Dataset'[visits] > [avg_visit]
)
```

**Use case:** Identify the segment of members visiting more frequently than average — potential candidates for premium upsell or loyalty rewards.

---

### Calorie Efficiency

```dax
Calorie Efficiency =
DIVIDE(
    SUM('Gym Dataset'[calories_burned]),
    SUM('Gym Dataset'[active_minutes]),
    0
)
```

**Use case:** Calories burned per active minute — reveals which activity types or demographics get the most output per unit of effort. Useful for programme design recommendations.

---

> **Note:** The measures above reflect the functional intent inferred from the data model. The exact DAX expressions are embedded in the `.pbix` file. Open the file in Power BI Desktop → **Model view → Measure_table** to inspect or modify them.
